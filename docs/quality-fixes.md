## 剩余限制

- 唯一生产依赖审计提示为 `mammoth → argparse → sprintf-js` 的无界精度参数拒绝服务问题；审计未提供已发布修复版本。源码核对表明 `argparse` 仅被 Mammoth 的命令行入口引用，应用使用的 `lib` 转换路径没有引用它。保留警告并等待上游修复，没有用不兼容覆盖隐藏提示。
- 移动测试是浏览器设备模拟，未覆盖实体手机、Safari、所有浏览器或生产云端 Chromium 环境。
- 未做生产并发压测、真实大规模简历库性能测试或付费模型连通性验证；294 kB 是构建产物指标，不能当作实际用户延迟或帧率测量。
- DOCX 保留原生可编辑内容和主要主题，不承诺复现任意自定义 CSS。扫描 PDF 仍需要 OCR；空提取会提示并保留已有稿件。
- API 密钥仍是当前浏览器 LocalStorage 中的明文数据。HTML 下载本地完成；PDF/DOCX 向应用服务器发送稿件；AI 向用户配置的服务商发送文本。

本次删除的是未使用依赖、废弃 CSS 常量和临时分页诊断测试；未删除已有回归测试或用户简历数据。配置修改前的备份位于本次会话的 `fix-backups` 目录。

## Hydration 与中等窗口宽度补充排查

用户反馈通用 hydration 警告后，直接检查了正在运行的 `http://localhost:3000`，并新增开发模式回归。当前页面刷新后控制台未捕获到该警告；仅凭通用错误文字不能确认原始触发原因，因此没有将下面的修复当作已经证明的原始警告根因，也没有扩大 `suppressHydrationWarning` 的使用范围。

本轮确认并修复了三处问题：

1. 首屏脚本忽略保存的主题和语言。阻止 React 脚本加载后，系统深色、保存浅色的页面仍呈深色；新增回归在旧实现上失败。现在首屏读取已保存设置，并在存储不可读时安全回退。
2. 开发和生产共用 `.next`。现在分别写入 `.next-dev` 与 `.next`；实际在开发回归期间运行了生产构建，开发检查继续通过。此项消除产物覆盖风险，未把风险描述成已证明发生的原始事故。
3. 640px 起过早启用桌面头部，导致导入/导出控件被遮挡。新增测试在旧实现在 640px 失败；修复后 320、390、640、768、820、1024、1280px 的按钮均在窗口内且可命中。中等宽度使用“更多操作”入口，足够宽时才展开完整操作栏。

新增 `e2e/hydration.spec.ts`，覆盖空存储、已保存中英语言及三种主题、系统深色、首次加载和刷新。交互用例增加自动 fixture，运行时异常、hydration、DOM 嵌套和无限更新警告会直接令测试失败。`playwright.dev.config.ts` 连接已运行的 3000 开发服务，使用独立测试产物目录。新增连续宽度回归覆盖之前遗漏的平板尺寸。

同时调整类型检查入口，先执行 `next typegen`，再执行 `tsc --noEmit`，避免新检出仓库尚未构建时缺少 `next-env.d.ts` 引用的生成路由类型。`packageManager` 固定为本机实际验证的 `pnpm@12.3.1`，使 CI 的 Corepack 使用相同版本。

最终补充验证：生产模式 50/50 通过（52.1 秒），开发模式 50/50 通过（1.5 分钟），均包含桌面与移动视口；开发模式完整回归期间未捕获到 hydration 或运行时异常。单元/组件回归 137/137 通过，头部变更后另跑 4/4 相关组件测试通过；lint、类型检查、生产构建通过。中等窗口截图位于 `test-results/workspace-header-actions-r-30dba-e-tablet-and-desktop-widths-desktop/tablet-header.png`。没有删除文件或用户数据。

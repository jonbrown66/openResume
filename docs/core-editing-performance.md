# 核心编辑性能与交互改造记录

日期：2026-10-18

本次覆盖输入与解析隔离、组合输入、内容撤销分组、焦点与选区恢复、不可变数据复用、异步分页取消和导出最新内容。未实施样式侧栏、页面虚拟化、IndexedDB 迁移或拖拽排序。

2026-10-18 继续收口“简历助手”的易用性和可读性：岗位描述按简历项目单独保存，请求失败/取消会保留可重新编辑的问题，等待状态显示耗时并可停止；对话使用安全 Markdown 渲染，候选稿只在用户确认后应用；完成对话切换简历后仍可恢复各自上下文。助手新增代码保持在空闲预加载模块内，首页 First Load JS 实测为 311 kB（当前未提交版本；先前文档记录的 301 kB 不是本版本的复测口径）。

同日收口长候选稿比较与多页预览：差异预览默认只渲染改动附近各两行上下文，完整对比仍可展开；超过 400 行或 16 万个比较单元的差异改用保留首尾相同内容的线性降级，避免矩阵内存和主线程开销继续放大。分页边界索引改为前缀最大值查询，避免每一页扫描全部行区间；首页完成后先挂载可读内容，其余页继续后台投影，导出仍等待全部分页完成。页面投影继续保留完整 DOM 结构，以维持 `:nth-child` 等选择器与跨页容器布局语义。

## 实现

- Markdown 输入立即更新编辑状态与持久化源文本；停止输入 80ms 后解析最新版本。切换项目会取消待处理任务；切换区块模式时立即取得当前内容。
- 输入法组合期间保留源文本，推迟预览；同一组合操作保持一条撤销记录。浏览器用合成 composition 事件验证，未验证 Windows 原生输入法的候选窗。
- 连续输入按字段分组；章节或条目的增删、排序独立记录，之后的输入重新分组。撤销/重做保存结构快照，并恢复仍存在的输入控件焦点与选区。样式历史不在本次范围内。
- 已有 ID 的未修改对象保留引用；重新解析时复用相同位置的未改变章节、条目与基本信息。当前没有建立任意 Markdown 重排的跨版本节点身份映射。
- 分页仍保留完整源 DOM 的选择器与排版语义，逐页生成投影并让出主线程。过时任务取消，全部页面完成才替换预览；重复尺寸通知不再无条件重算。
- Word 导出直接读取点击时的最新源文本。PDF/HTML 等待分页就绪后读取内容和字体，避免预览延迟导致旧内容或缺少新字形。
- 样式数字框的键盘上下步进立即应用，文字输入仍在回车或失焦时提交。

## 性能记录

生产构建、桌面 Chrome、1280×900、CDP 4 倍 CPU 降速；普通样本 4 条经历 / 1 页，长样本 40 条经历 / 7 页。每个样本连续输入 42 个字符。基线使用本轮改造前、已包含上一轮存储与控件修复的生产构建。

| 指标 | 改造前 | 改造后 |
| --- | ---: | ---: |
| 1 页：input 事件到下一个 rAF，P50 | 14.5ms | 10.8ms |
| 1 页：input 事件到下一个 rAF，P95 | 49.4ms | 27.4ms |
| 1 页：最长 Long Task | 73ms | 62ms |
| 7 页：input 事件到下一个 rAF，P50 | 19.3ms | 19.6ms |
| 7 页：input 事件到下一个 rAF，P95 | 71.2ms | 41.9ms |
| 7 页：Long Task 次数 | 11 | 8 |
| 7 页：最长 Long Task | 509ms | 257ms |
| 7 页：DOM 节点数 | 2560 | 2560 |
| 停止输入后轮询观察到预览就绪，1 页 | 24ms | 297ms |
| 停止输入后轮询观察到预览就绪，7 页 | 796ms | 1260ms |

这是每种实现的一轮本机观测，不是多轮统计或线上 INP。input-to-rAF 不等于真实完成绘制；就绪等待受 Playwright 轮询间隔影响，不能当作精确的预览延迟。P95 输入等待改善，长文档预览追赶没有被证明更快，仍有约 257ms 的长任务；这轮不能宣称所有操作都达到流畅性目标。

分批处理减少单次连续阻塞，也增加了预览追赶的等待。后续应先定位剩余长任务来自文本测量、页面克隆还是 DOM 提交，再决定进一步分块或页面挂载优化。本轮已让首页在其余页完成前可先显示；当前浏览器环境拒绝访问 `127.0.0.1`，没有取得改造后的多页就绪数值，不能把“更早看到首页”写成已验证的延迟数字。

复现命令：

```powershell
pnpm build
pnpm exec playwright test e2e/editing-benchmark.spec.ts --project desktop --workers 1 --output output/performance-optimized --reporter list
```

改造后的原始测量保存在 `output/performance-optimized/` 每个测试目录内的 `editing-benchmark.json`。
